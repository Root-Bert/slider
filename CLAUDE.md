# Slider – rules for coding agents

Read by Claude Code (`CLAUDE.md`) and Codex (`AGENTS.md` is a symlink to this file). Deep,
tested facts (LibreOffice, voice, Unsplash, AI context, local services) live in
[`docs/agent-notes.md`](docs/agent-notes.md) – read the matching section before touching that
area. Repo facts go here or there, not into private agent memory.

## 1. Do not break (check before you finish)

The user judges Slider by these. Each one was right once and came back broken later. When
your change touches the area, run the check and say in your report that you did.

## 2. Working in this repo

- **Work directly on `main` in the main checkout** – no worktrees, no branches. Several agents
  (Claude, Codex) may write the same checkout at once, so touch only your own files.
- **Never `git stash`, `git checkout -- <file>` or `git reset`** to compare with HEAD – it wipes
  other agents' unfinished work. To see whether a failure is pre-existing, read the diff or copy
  the test to `test/zz-*.test.ts` and delete it after. Failures in files you did not touch are
  probably someone else's work in progress: report, don't "fix".
- **Commit small and only your own files.** One commit per change with a short subject; no
  `git add -A` over a tree holding other agents' work.
- **Git is reserved for the user: never push.** Commit on `main`, then stop – the user pushes;
  no `git push`, no PR. No AI co-author: never add
  `Co-Authored-By:` or „Generated with …“ lines to commits or PRs.
- **Dev server:** never start a second `bun run dev` while one runs (`lsof -iTCP:8787`) – two
  processes on one PGlite dir broke the WAL and the DB had to be thrown away.
- **Migrations:** never edit `schema.ts` temporarily while the dev API (`bun --watch`) runs – it
  restarts and migrates, and drizzle applies each migration file only once by timestamp, so a
  half-written file sticks. Generate with the API stopped, or write SQL + snapshot by hand. If a
  dev DB is half-migrated: stop the API (PGlite allows one process), fix with a one-off script.

## 3. Checks

- Typecheck web with `cd apps/web && npx tsc --noEmit -p tsconfig.app.json` (or `tsc -b`).
  `tsc -p .` in apps/web checks **zero** files (`"files": []`). api/shared: `-p tsconfig.json`.
  Whole repo: `bun run typecheck`. Filter other agents' errors to the files you touched.
- Tests: `bun run test`, `bun run e2e` (see [`docs/testing.md`](docs/testing.md)). **Budget: at
  most 500 tests in the whole repo** (each `it.each` row and each Playwright case counts). Add
  assertions to an existing `it` instead of new cases; merge rather than drop security coverage.
- e2e disables LibreOffice (`LIBREOFFICE_PATH: '/nonexistent/soffice'`), so the editor never
  opens there. To see the editor, copy the config with
  `/Applications/LibreOffice.app/Contents/MacOS/soffice`, own ports/data and a longer timeout,
  run a scratch spec, delete both after. `POST /api/decks/blank` gives an editable ODP (new
  element ids match `^sl[a-z0-9-]{4,60}$`); enter edit mode via
  `getByRole('radio', { name: 'Bearbeiten' })`; screenshots `E2E_SHOTS=1 E2E_SHOTS_DIR=<dir>`.
  Measure editor speed with `waitForFunction(..., { polling: 'raf' })`, not `locator.waitFor`
  (polls every 500 ms).
- Visual work is not done until you have looked at it (screenshot or parity script).

## 4. Product rules (every UI change)

- **One behaviour, everywhere.** Before building a menu, dialog, panel, shortcut, selection or
  route for X, find how Präsentationen do it (`features/reviews/components/DeckActions.tsx`) and
  copy label, icon, confirm dialog, toast and keyboard. Never invent a new mode; never ask per
  place. When fixing one place, grep its siblings and fix them in the same go.
- **Wording:** a deck is „Präsentation“/„Präsentationen“ (never „Idee“, except in its everyday
  sense). Destroying something own = „Löschen“ (menu, „X löschen?“, button „Löschen“, toast „X
  gelöscht“) – also Vorlagen, Schriften. „Entfernen“ only when a link goes and the thing stays
  (member, key, logo). Neutral words („Präsentation“, „Datei“, „Link“); vendor names only where
  the vendor is meant (Microsoft login, OneDrive picker, Unsplash credit).
- **Panels:** every floating panel/popover/dialog loops Tab via `useFocusLoop` (built into
  `usePopover`, `Dialog`); menus excepted. Rows of choices stepped while nothing is focused go
  through `tabStep` (`lib/dom.ts`) – never a hand-written Tab handler. A row of choices always
  has one picked from the start and shows its panel at once.
- **No spinners once a deck exists.** Every edit is instant or optimistic (shown at once, sent
  through the outbox, a refusal toasts) – a panel closes on the pick, it never waits for the
  server. Spinners only where something really has to arrive: pictures downloading, the AI
  working.
- **Editor states:** every shortcut/action works in every state – element picked, typing, focus
  in a panel `<select>`, template editor, foreign clipboard. Use `isTextTarget` (`lib/dom.ts`).
- **The editor feels like a lighter Figma** – a PPTX with another UI: the file stays a real
  presentation (what LibreOffice/PowerPoint show), the way of working is Figma's. When unsure how
  an editor control should behave, do it as Figma does (3×3 text alignment, snapping to the slide
  and guides, locking, layers, direct handles), only simpler – fewer options, no modes.
- **Editing is Slider's own UI:** no office iframe (Collabora/ONLYOFFICE/WOPI), never a side
  panel in edit mode – formatting lives in the floating `FormatBar` over the element; undo/redo/
  save/download in the tool bar. Esc, ⌘↵ and ✕ take the element as it is and deselect. Every
  text box and shape with text is typable (only fields, numbering, symbol fonts, rotated text
  are not). Hand-editing scope: text (font, size, colour, B/I/U, alignment) and box (position,
  size, fill, border); anything complex is left to the AI.
- **Template colours** are defined in the template („Farben“ in `TemplateControls`); decks from
  it offer only its palette plus „Eigene“ (`ColorPalette.tsx` for every colour dot). No separate
  colour library. Open: several themes per template, ODP theme refs (notes §LibreOffice).
- Design tokens and primitives: [`apps/web/design-system.md`](apps/web/design-system.md).
- Prefer minimal fixes; measure before rebuilding. Complicated additions that don't help get
  reverted.
